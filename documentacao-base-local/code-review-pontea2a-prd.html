✅ Depois — opção A (atualizar links)

2. Segurança

Os checks SEC-01..SEC-08 do CLAUDE.md (IDOR, @PreAuthorize, migrations) pressupõem endpoints REST/JPA que não existem neste artefato. Abaixo, os pontos de segurança que o próprio conteúdo do PRD deveria cobrir.

SEC Aprovado — nenhum segredo real exposto 🟢 OK

O PRD nunca inclui um valor de REQUEST_STATE_SECRET real, apenas o comando para gerar um (seções 7 e 19). Consistente com a exigência de não commitar segredo em repositório público.

SEC Aprovado — opacidade do requestState corretamente especificada 🟢 OK

Seção 14 deixa explícito que o requestState nunca é exposto em card, artifact ou mensagem A2A, e que o agente nunca o interpreta.

VULN-01 Aviso de "nunca versionar o segredo" perdido na condensação 🟡 Média

Categoria Gestão de segredos (equivalente adaptado a OWASP A05 — Security Misconfiguration)

Onde Seção 19 ("Como rodar") do PRD, comparado com 00-08-readme.md.

Cenário de ataque Alguém segue só a seção 19 do PRD — que promete ser "quase autossuficiente" — não vê o aviso, cria um .env com o segredo gerado e commita por hábito.
Impacto Vazamento do segredo em repositório público, invalidando a integridade do requestState para qualquer entrega feita com aquele segredo.
✅ Correção
> `REQUEST_STATE_SECRET` precisa estar exportado no terminal do `servidor-mcp` **antes** de subir o processo. Nunca versione o valor usado — apenas o comando para gerá-lo (o repositório é público).
